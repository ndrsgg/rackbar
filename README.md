# Rackbar

Every server in every Hetzner Cloud project, one click away in the macOS menu
bar — with the addresses you keep pasting into a terminal, the state of each
machine, and an ssh config that writes itself, so `ssh acme/web-1` and
`ssh acme/<Tab>` just work. Read-only by design: it lists, it copies, it never
powers anything on or off.

The macOS sibling of [omarchy-hcloud](https://github.com/ndrsgg/omarchy-hcloud),
the same idea for the Omarchy bar.

> **Status: early.** The core (API, merging, ssh config) is tested; the app
> is a first cut. Not affiliated with Hetzner Online GmbH.

## What it does

- **All projects, one list.** One read-only token per Hetzner project,
  grouped under labels you choose. Several projects under one label share one
  heading and one ssh namespace.
- **Copy, don't retype.** Click a row for its IPv4; the menu has the name,
  IPv6, private IP and the ssh alias. Storage Boxes too, with how full they are.
- **ssh that just works.** Every server with a public IPv4 becomes
  `Host <label>/<server>` — in ssh, scp, rsync, mosh and your shell's tab
  completion.
- **State at a glance.** Filled dot running, hollow off, pulsing while it
  changes, red when something is wrong.

## The ssh config, and why Rackbar never sees your keys

Rackbar runs in the App Sandbox. It does not get `~/.ssh`. It gets one folder
of its own that you create and pick once, say `~/.ssh/hcloud`, and it owns the
one file in there:

```
~/.ssh/
├── id_ed25519        ← Rackbar cannot see this
├── config            ← nor this
└── hcloud/           ← the only folder you granted
    └── config        ← written by Rackbar
```

You add two lines at the **end** of your own `~/.ssh/config`, once — the
settings window has them, and a command to paste:

```
Match all
Include hcloud/config
```

At the end, because ssh takes the first value it finds: anything you set above
wins over the generated entries.

```
Host acme/*
    User deploy
    IdentityFile ~/.ssh/work_ed25519

Host acme/db-1
    ProxyJump acme/bastion

Match all
Include hcloud/config
```

`Match all` closes whatever `Host` block came last; without it the `Include`
would only apply inside that block.

What the sync will not do:

- **Write from an incomplete picture.** If any project failed to load — an
  expired token, a dropped network — nothing is written. Writing would delete
  that project's hosts over a passing error.
- **Write anything ssh might misread.** Names outside `[A-Za-z0-9._/-]`, an
  address that is not an IP, a user or key path with whitespace: the whole job
  is refused and the settings say which one. The file is read by ssh, and a
  stray newline in a server name would smuggle in a `ProxyCommand`.
- **Churn.** The file is written atomically with mode 600, and not at all when
  nothing changed.

### Tab completion

zsh, fish and bash-completion all follow `Include`. zsh completes hosts only
with its completion system on, which the stock macOS `~/.zshrc` does not do:

```zsh
autoload -Uz compinit && compinit   # before zsh-syntax-highlighting and friends
```

## Tokens

Create one per project in the Hetzner Cloud Console under **Security → API
tokens → Generate** with **Read** permission. Rackbar tries the token before
it keeps it, then stores it in the data protection Keychain, readable after
first unlock and never synced. It is not written to UserDefaults, not passed on
a command line, and only `HetznerClient` builds an `Authorization` header from it.

A refresh costs three requests per token — servers, volumes, storage boxes —
made side by side. Opening the menu does not refetch unless the list is older
than the refresh interval or failed. A project that fails a round keeps the
list it showed last round, marked as such.

## Building

Requires Xcode for macOS 27 and [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
brew install xcodegen
cp Config/Local.xcconfig.example Config/Local.xcconfig   # put in your team ID
xcodegen
open Rackbar.xcodeproj
```

A development team is needed even for local runs: the data protection
Keychain refuses unsigned builds.

## Layout

| Path | What |
| --- | --- |
| `RackbarCore/` | Swift package, Foundation only: the Hetzner client, merging tokens into projects, the ssh config renderer and writer. Runs on Linux too. |
| `App/` | The SwiftUI app: menu bar panel, settings window, Keychain, the sandboxed folder grant. |
| `App/Rackbar.entitlements` | Everything the sandbox lets Rackbar do. |
| `project.yml` | The Xcode project, generated by XcodeGen. |

## Tests

```bash
cd RackbarCore
swift test                     # offline
RACKBAR_LIVE=1 swift test      # plus one request against the real API, no token needed
```

## Not yet

- A page per server with live CPU, disk and network

- A desktop widget (WidgetKit) and Shortcuts actions

Things it deliberately does not do, and will not take patches for: power
actions on servers, and anything that puts a token anywhere but the Keychain.
